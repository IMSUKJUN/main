# Claude Page View

Claude 대화의 세로 스크롤을 가로 페이지 구조로 바꿔 보여주는 크롬 확장 프로그램.

카드 한 장이 페이지 한 장이고, 한 페이지는 화면 안에 온전히 들어간다. 위아래로 잘려
나가는 부분이 없다.

## 지금 되는 것

- 대화 전체를 가로 카드 트랙으로 그린다
- 1차로 샷(질문 하나 + 답변 하나) 단위, 2차로 길이 단위로 페이지를 나눈다
- 문단·목록·제목·표·코드블록을 페이지 경계에서 자르지 않는다
- 프롬프트는 그 샷의 **모든 페이지 위에** 붙어 있다. 다음 샷으로 넘어가야 바뀐다
- 프롬프트는 한 줄로 접히고, 펼치면 아래 카드 **위에 겹쳐서** 펼쳐진다 (카드는 안 밀림)
- 카드 폭은 원래 스크롤 화면의 글줄 폭과 같다. 줄바꿈이 스크롤 화면과 같아진다
- 도구 실행 내역은 접힌 한 줄로 두고, 펼치면 **본문 오른쪽에** 페이지로 붙는다 (`T1`, `T2`…)
- 세션 상태(`세션 재개됨` 등)는 카드 사이에 칩으로 세운다
- 카드마다 얇은 선과 연한 그림자가 붙어 페이지끼리 구분된다
- 중앙 카드만 또렷하고 좌우는 바깥으로 갈수록 흐려진다
- 이동: 휠(연속 스크롤, 멈추면 가까운 페이지에 맞춤) / 드래그 / 좌우 카드 클릭 /
  좌우 카드 클릭 유지 / 좌우 화살표 / 아래쪽 스크롤바 끌기
- 가운데 아래에 `4 / 21 · 4p` 로 지금 위치가 나온다
- 페이지 번호는 카드 안 우하단, 액션 바는 중앙 카드 아래에만

## 설치

1. 크롬에서 `chrome://extensions` 열기
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** 를 눌러 이 폴더를 고르기
4. claude.ai 에서 오른쪽 아래 **페이지 보기** 버튼 또는 `Alt+P`

`Esc` 로 원래 스크롤 화면으로 돌아온다.

## 어떻게 동작하나

claude.ai 대화창은 두 가지 성질이 있고, 이게 구조를 결정했다.

**앱 DOM 은 읽기만 한다.** React 가 만든 노드를 다른 곳으로 옮긴 뒤 React 가 그것을
지우려 하면 `removeChild` 오류가 나면서 메시지가 통째로 사라진다. 그래서 원본 대화는
손대지 않고, 읽어서 우리 레이어에 다시 그린다.

**대화창은 가상 스크롤이다.** 화면 밖 행은 DOM 에 없다(실측: 44행 중 4~15행만 존재).
그래서 켤 때 대화를 한 번 훑어 내려가며 각 행이 나타날 때 복제해 둔다(`src/harvest.js`).

**페이지 나눔은 CSS 다단이 한다.** 한 덩어리를 `column-count` 로 흘리면 브라우저가
줄 단위로 정확히 나눠 준다. 카드 테두리는 `box-decoration-break: clone` 이 조각마다
온전히 그려 주기 때문에, 페이지 수만큼 요소를 복제할 필요가 없다.

**코드블록은 shadow DOM 이라 복제하면 비어 있다.** `.epitaxy-diff` 의 `data-code-text`
속성에 원본 코드가 그대로 남아 있어서 그것으로 되살린다(`src/source.js`).

## 고친 것

**0.1.5** — 대화를 다 못 읽던 문제의 진짜 원인.

수집은 스크롤을 한 칸씩 내리며 그때 붙어 있는 행을 복제하는 방식이다. 문제는 "언제
다음 칸으로 넘어갈지"였다. 처음에는 150ms 고정으로 기다렸는데, 앱은 스크롤 직후가
아니라 한 박자 뒤에 행을 붙이고 그 시간이 일정하지 않다. 다음으로 "붙어 있는 행이
더 안 바뀌면 넘어간다"로 바꿨더니 더 나빠졌다. **앱이 아직 시작도 안 했을 때도 안
바뀌기 때문**이다. 모사 화면에 220ms 지연을 넣자 27행 중 5행만 읽혔다.

이제 **지금 보이는 자리에 행이 실제로 걸쳐 있는지**를 보고 넘어간다. 시간에 기대지
않으므로 앱이 느리든 빠르든 같은 결과가 나온다. 같은 모사에서 27행 전부를 읽는다.

같이 고친 것: 애니메이션 스크롤(`html.scroll-smooth`)을 수집 동안 꺼서 위치를 정확히
짚게 했고, 맨 아래로 끌어당기는 동작(`data-autoscroll-container`)에 밀리면 다시 밀어
넣는다. 빠진 곳 검사는 `data-perf-row-from-tail`(끝에서 몇 번째)로 전체 행 수를 알아내
0번부터 끝까지 본다. 예전에는 읽은 것들 사이만 봐서 맨 위를 통째로 못 읽어도 "빠진
것 없음"으로 나왔다. 빠진 번호가 있으면 이웃 행의 위치를 보고 그 자리로 직접 가서 줍는다.
원본 대화를 감추는 것도 수집이 끝난 뒤로 미뤘다.

**0.1.4** — 실제 화면에서 나온 세 가지.

프롬프트가 아예 안 보이던 문제. 실제 화면에서는 사용자 메시지와 답변의 `entry-index` 가
서로 다르다(`human` 0, `assistant` 1, `human` 2 …). 그 번호로 샷을 묶다 보니 사용자 행이
혼자 샷이 되고 답변 쪽에는 프롬프트가 없어 말풍선이 안 그려졌다. 이제 번호가 아니라
**사용자 행이 나오면 새 샷이 시작하는 것**으로 묶는다. 모사 화면도 실제처럼 번호를
다르게 주도록 고쳐 회귀를 잡는다.

대화를 다 못 읽던 문제. 행 높이를 재는 동안 전체 높이가 계속 바뀌는데 처음 읽은 높이로
한 번만 훑고 끝냈다. 이제 바닥에 닿을 때까지 매번 높이를 다시 읽으며 돌고, 그러고도
빠진 번호가 남으면 절반 간격으로 한 번 더 훑는다. 다 읽으면 몇 개를 읽었는지,
못 읽은 줄이 있으면 몇 개인지 화면에 잠깐 띄운다.

스크롤바가 안 보이던 문제. 브라우저 기본 스크롤바는 OS 설정에 따라 자리를 아예 안 차지해서
(headless 측정값 0px) 직접 그리는 것으로 바꿨다. 끌어서 이동할 수 있고, 가운데 아래에
`4 / 21 · 4p` 형태로 지금 위치도 같이 나온다.

**0.1.3** — 세 가지.
프롬프트를 그 샷의 모든 페이지 위에 붙였다. 페이지를 넘겨도 같은 질문이 위에 남고
다음 샷에서 바뀐다. 휠을 한 칸씩 넘기던 것에서 연속 가로 스크롤로 바꾸고 멈추면
가장 가까운 페이지에 맞추게 했다. 트랙에 가로 스크롤바도 넣었다.
카드 폭은 원래 스크롤 화면의 글줄 폭을 읽어 거기에 맞춘다. 줄바꿈이 스크롤 화면과
같아지고, 카드보다 넓어서 잘리던 표 문제도 같이 없어졌다(경계 걸침 20줄 → 0줄).

**0.1.2** — 페이지끼리 구분되도록 카드에 얇은 선과 연한 그림자를 넣었다.
`box-decoration-break: clone` 덕에 그림자도 조각(페이지)마다 온전히 그려진다.
그림자 색은 화면 밝기를 보고 정해서 다크 모드에서도 보인다.

**0.1.1** — 페이지 보기에서 원본 대화가 비쳐 보이던 문제. 원인은 앱의 색 변수였다.
claude.ai 의 `--bg-100`, `--text-100` 등은 색이 아니라 HSL 숫자 세 개(`48 33.3% 97.1%`)라서
`background: var(--bg-100, #faf9f7)` 처럼 쓰면 변수가 정의되어 있으니 대체값이 안 먹고,
색으로는 무효라 배경이 투명해진다. 이제 실제로 그려진 색을 읽어서 쓴다(`src/source.js` 의 `theme()`).
여기에 더해 페이지 보기 동안에는 원본 대화를 규칙으로 감춘다(`html.cpv-on`). 자리는 그대로 두어
가상 스크롤이 계속 동작한다. 덮개 밖(사이드바·입력창)은 그대로 쓸 수 있다.

## 남은 것

- 창이 아주 좁으면 카드 폭이 글줄 폭보다 작아지고, 그때는 표가 카드 안에서 가로로
  스크롤된다. 가로 드래그 이동과 겹치는 조작이라 손봐야 한다
- 생성 중 표시를 앱의 신호(`data-perf-row-streaming`, `aria-busy`, shimmer)와 연결하기
- 액션 바가 지금은 모양만 있다. 원본 버튼과 연결 필요
- 대화를 옮길 때(SPA 이동) 다시 수집하기
- 수집이 끝나기 전에도 쓸 수 있게 점진 표시
